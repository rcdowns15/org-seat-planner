# Org Seat Planner

Engineering leaders at **Second Republic Bank**, a fictional company, plan their org in a write-back app.
They move people between squads, and every move is validated on the server, saved with optimistic
locking, and recorded in an append-only audit trail. A pipeline ingests biweekly mock Workday
reports, and dbt reconciles HRIS facts against the leaders' plan (headcount vs. plan, refresh
changes, exceptions to drive to zero).

> **All data is fictional**, generated by a seeded script. Second Republic Bank isn't a real company,
> and no real people or systems are represented.

**Production:** https://org-seat-planner.vercel.app (health check: `/api/health`).

> **Work in progress.** The live demo, architecture diagram, demo script and production mapping
> arrive in BR-04. See [`docs/MASTER_PLAN.md`](docs/MASTER_PLAN.md) for scope and status.

## Development

Needs Node 24 (`.nvmrc`) and pnpm (`corepack enable`; version pinned in `package.json`).

```
pnpm install
pnpm dev          # http://localhost:3000
pnpm lint         # ESLint + Prettier check
pnpm typecheck
pnpm test         # Vitest unit tests
pnpm test:e2e     # Playwright (first run: pnpm exec playwright install chromium)
pnpm build
```

## Local database

```
docker compose up -d db             # Postgres 16 on 127.0.0.1:5432; schemas app/workday/analytics created
cp .env.example .env.local          # DATABASE_URL points at the compose database
pnpm db:migrate                     # apply db/migrations (uses DATABASE_URL_UNPOOLED, else DATABASE_URL)
pnpm db:seed                        # wipe and reseed app + workday; writes data/workday/*.csv; prints a checksum
pnpm db:seed:check                  # print the checksum of the seeded rows (see scripts/seed/README.md)
pnpm workday:ingest <file>          # validate and load one Workday report CSV (e.g. data/workday/worker_report_2026-11-15.csv)
pnpm test:db                        # migrates, then runs constraint and schema tests (local DB only)
curl -i localhost:3000/api/health   # 200 {"ok":true,"db":"ok","seats":N} (N = rows in app.seats: 0 before db:seed); 503 when the database is down
```

`pnpm db:seed` prints the target host and refuses any database that isn't `localhost` or
`127.0.0.1` unless you pass `--allow-remote`, so a stray production `DATABASE_URL` (for example
after `vercel env pull`) can't be wiped by accident.

### Deploying the database (Neon)

The `db-deploy` GitHub Actions workflow is manual (Actions tab, Run workflow). It runs
`pnpm db:migrate` against the `NEON_DATABASE_URL_UNPOOLED` secret, and runs
`pnpm db:seed --allow-remote` only when the `reseed` input is `true` (that wipes and reseeds Neon).

Schema changes: edit `db/schema/*.ts`, run `pnpm db:generate`, commit the new file in
`db/migrations/`, and update `docs/data-model.md` (a test checks it against the database).
Hand-written SQL (triggers, grants) goes in `pnpm db:generate --custom --name=<what>`.
Seats match Workday workers by `worker_id` only; they aren't linked to Workday positions yet (D-029).
